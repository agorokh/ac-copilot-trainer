AC Copilot — Claude Design visual package

The in-game HUD is the source of truth. It's already Figma-matched and shipped (PR #70/#73). This package reproduces it faithfully from src/ac_copilot_trainer/modules/hud.lua + coaching_overlay.lua — same colours, sizes, and the real bundled typefaces (Michroma · Montserrat · Syncopate) — then aligns the Windows launcher and the ESP32 rig screens up to that language so all three surfaces read as one product. Open in a browser; pair with the written brief 15_Claude_Design_UI_Package.md.

1 · In-game HUD — north star (reproduced from source)

Two ImGui overlay windows, drawn absolute-positioned (no widgets): a centred Active Suggestion tile and a structured Approach panel. Translucent #111 @ 60% glass, grey hairline, Michroma numerics, red eyebrow / amber secondary / green-white-red speed semantics, Syncopate brand footer.

Surfaces & line

Semantic colour

Rules

Centre the suggestion, structure the data.
One action line + one reason.
Colour = state, never decoration.
Numbers are Michroma, labels are small-caps grey.
Rig screen 320×480 · tap floor 60px.

3 · Windows Game Point launcher (aligned to the HUD)

Same glass + grey-hairline + Michroma-numeral + small-caps-grey-label language as the HUD. Status rows map 1:1 to GamePointStatus (tools/rig_launcher/supervisor.py); state words are the verbatim probe strings. Colour carries state (green healthy, red blocked, grey absent); gold stays only on the primary action.

5 · Extending this package

The HUD stays the reference; new surfaces align to it. When a screen, state, or status row changes, update this file and 15_Claude_Design_UI_Package.md, and keep each change in the surface that owns it: CSP Lua HUD (src/ac_copilot_trainer/modules/), Tkinter launcher (tools/rig_launcher/), or LVGL firmware (firmware/screen/src/ui/). If the HUD's Figma source moves, re-sync the tokens here from hud.lua / coaching_overlay.lua first.
