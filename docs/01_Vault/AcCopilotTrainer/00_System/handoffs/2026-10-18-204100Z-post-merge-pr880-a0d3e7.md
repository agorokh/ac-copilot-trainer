## Two things worth keeping

1. **The closing-keyword trap bit this very PR.** The first commit message and PR body contained
   "continues the closed #813"; GitHub parsed `closed #813` as a closing reference
   (`closingIssuesReferences=[813]`) and the pinned close-intent gate reported "will close: #813"
   — on a PR whose whole point was recording that #813 had been auto-closed against intent.
   Reworded both (`#813 (already CLOSED)`), amended with `--force-with-lease`, closing refs went to
   `[]`. Rule: never let `closed|closes|fixes|resolves` sit directly before `#N` in a PR body or
   commit unless this merge closes N. See `pitfalls/linkage-autoclose-against-intent.md`.
2. **The hub vault sweep cannot land this repo's vault PRs.** `vault_sweep_discover.py` (gov-hub
   runs `39162816135`, `39163628410`) skips `ac-copilot-trainer#880` with
   `caller-unreadable (vault-automerge.yml: local hub action lacks a bound canonical checkout)` —
   this repo checks the action out by SHA into `.governance-hub/` and `uses:` a local path (issue
   #329 workaround), which the sweep's caller reader does not recognise. So a vault PR whose
   `opened`/`labeled` run races the daemon lease (2-second race seen twice here: `18:59:57Z`,
   `20:01:38Z`) stays open until someone re-fires a `labeled` event or merges by hand. Durable
   escalation for governance-hub; not filed from here.
