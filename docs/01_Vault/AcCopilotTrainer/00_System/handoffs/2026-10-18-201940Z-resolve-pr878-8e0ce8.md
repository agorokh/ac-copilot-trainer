GitHub's `closingIssuesReferences` held #813 because the PR body quoted PR #848's disclaimer as
*"says it does not close #813"*. A negated closing keyword is still a closing keyword
(gov-hub#621; the mcp-servers#440 shape the gate was built for). The sentence was reworded to
*"disclaims #813 as a closing target"*; `closingIssuesReferences` emptied, the gate returned
`ADMIT: ok` (eight `Refs`-only issues, nothing closing), and the head did not move. The hub
vault-pr-sweep would have kept refusing: the blocker was body text, not the head. #813 was
already CLOSED, so the refusal protected nothing live here — but the same text on an open
tracker would have auto-closed it a second time.
